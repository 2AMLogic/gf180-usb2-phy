- **Result**:
  - **SDF route / layout case.** `klt place-and-route` can export a
    post-route SDF (`post_route_sdf`, which requires `post_route_spef`), but
    only inside the P&R run, at the request's own `pdk.corner`. Re-running
    it (request `flow/request-usb-utmi-phy-par-sdf.json`, seed 1) fed the
    **committed** synthesized netlist
    (`place-and-route/artifacts/20260922-042422-9ec2304/usb_utmi_phy_synth.v`)
    and reproduced **`usb_utmi_phy.def` and `usb_utmi_phy_routed.v`
    byte-for-byte** (sha256 equal). The re-minted GDS differed in bytes from
    the committed one (cell/shape ordering; identical with klayout 0.30.10
    and 0.30.12, so not a version effect) but is geometrically identical:
    a KLayout per-layer XOR of the two GDS files is empty on every layer.
    The re-run GDS was **not** committed; the committed GDS stands. So the
    layout was **not** re-generated and no dependent signoff citation moves
    (DEF and GDS in the tree are byte-identical to before). Re-running
    `klt synthesize` on this host did not reproduce the committed synthesized
    netlist (host Yosys 0.67+post vs the committed netlist's 0.69+post: one
    net name differs), which is why the committed netlist was staged as the
    P&R input instead of re-synthesizing.
  - **SDF corners.** `klt` emitted one SDF, at `tt_025C_1v80`
    (`usb_utmi_phy_route_tt_025C_1v80.sdf`). The slow-corner SDF
    (`usb_utmi_phy_route_ss_125C_1v62.sdf`) has no `klt` route from an
    existing routed DEF (filed as klayout-tools#2886), so it was produced by
    the same OpenSTA script `klt` generates for the post-route SPEF session
    with only the `read_liberty` swapped (`write-sdf-ss_125C_1v62.tcl`) and
    `write_sdf -divider . -include_typ`. It is therefore outside `klt`'s own
    provenance and is disclosed as such. The parasitics read are the
    P&R-internal route SPEF, not the `klt extract` SPEF of record
    `post-layout-pvt/20261008-195826-74ccfac`. For that SPEF, `read_spef`
    was shown to take effect here (a no-SPEF replay at `tt` differs from the
    SPEF one in 4748 SDF lines), unlike the extracted-SPEF case #106 tracks;
    `INTERCONNECT` entries are nonetheless all 0.000 ns (sub-picosecond wire
    delay at 3-decimal resolution), so the delay content is IOPATH cell
    delays carrying the parasitic loads. The SDF's `min:typ:max` members are
    largely equal (single-liberty SDF); `-T max` was used for the `ss` run.
  - **Zero-delay gate-level replay** (`response-gate-zero-delay.json`, no
    `options.sdf`, so `environment.sdf: null`): `status: "pass"`, 10 tests
    run, 10 passed, 0 failed, 0 skipped — the full existing
    `test_usb_utmi_phy.py` inventory (reset state, SYNC pattern, EOP tail,
    single-byte and multi-byte stuffed loopback, leading-ones stuff scope,
    trailing-six-ones flush, minimal-gap back-to-back packets, raw mode,
    malformed SYNC) against `usb_utmi_phy_routed.v` plus the PDK models. This
    is **not** item-7 evidence (the grader renders an unannotated run
    `not_post_layout`); it is the diagnostic that isolates the blocker.
  - **Testbench adaptation** (`verification/test_usb_utmi_phy.py`): the
    packet driver's internal `dut.tx_state` read was replaced by an
    externally observable completion condition (the EOP tail SE0,SE0,J was
    seen on `txdp`/`txdm` and `TxReady` is high again; the routed netlist
    re-encodes `tx_state` one-hot, so the RTL's value-0 test is meaningless
    there). The RTL regression still passes 10/10 with sim times identical to
    the committed records (e.g. back-to-back `13541.775 ns`), so no check was
    weakened. The test also gained the env override
    `USB_UTMI_PHY_TB_CLK_PERIOD_PS` (unset by default) so a negative-control
    run can change the clock the testbench itself starts.
  - **SDF-annotated replay: blocked.** All of the following are `klt` error
    envelopes (exit 1), not test verdicts. `klt` reported no test results
    for them. Icarus still ran the cocotb suite with the SDF partially
    applied: each committed transcript ends `TESTS=10 PASS=10 FAIL=0`. Icarus
    skips the arcs it cannot match and exits 0, so that summary comes from a
    **partially annotated** netlist. It is not a post-layout timing result,
    and `klt` was right to discard it. It is disclosed here only because the
    transcripts show it:
    - `klt 0.5.0`, `ss_125C_1v62` SDF, `-T max`: 64 diagnostics.
    - `klt 0.5.0`, `tt_025C_1v80` SDF, `-T typ`: 64 diagnostics.
    - `klt 0.7.0`, `ss_125C_1v62` SDF, `-T max`: 63 diagnostics (the
      `RxActive` top-level-port `INTERCONNECT` "Could not find intermodpath"
      is gone; the rest remain).
    Breakdown of the 64 under `klt 0.5.0` (`icarus-transcript-*.log`):
    62 `Unable to match ModPath <in> -> <out>` plus 2 `Could not find
    intermodpath!` (one top-level-port `INTERCONNECT`, one deferred
    bus-port entry). The ModPath mismatches are on XOR2, XNOR2 and MUX2
    instances (23 instances; `S -> Z`, `A1/A2 -> Z/ZN`). Cause: the PDK
    models give these non-unate arcs edge-qualified paths
    (`ifnone (posedge A1 => (Z:A1))` / `negedge`), while OpenSTA's
    `write_sdf` emits two unqualified `(IOPATH A1 Z ...)` entries per
    input; Icarus cannot match them. Each transcript also has 73
    `TIMINGCHECK not supported` warnings, the benign class `klt` exempts.
    One of the 73 is split across lines by the interleaved cocotb summary
    table, so a full-line grep finds only 72. An earlier draft of this
    record said 72.
    Filed as klayout-tools#2885 (described generically). The
    annotation gate did its job: a zero-delay verdict was not reported as an
    annotated one.
  - **Negative control: not run.** A shortened-clock replay is only
    meaningful against an annotated run that passed at the nominal clock;
    against a zero-delay netlist a faster clock changes nothing, and an
    annotation-failure error envelope is an infrastructure failure, not a
    detection (issue guidance). The hook exists
    (`USB_UTMI_PHY_TB_CLK_PERIOD_PS`) for whoever unblocks annotation.
  - **Overall: blocked.** None of the issue's acceptance criteria for a
    successful annotated regression is met; `7.digital` stays `unmet`.
