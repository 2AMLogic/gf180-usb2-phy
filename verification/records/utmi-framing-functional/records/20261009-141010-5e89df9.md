# Record 20261009-141010-5e89df9

- **Record ID**: 20261009-141010-5e89df9
- **Claim**: UTMI `Reset` during *transmission* (issue #130). It aborts
  the packet on the edge that samples it, and the first packet after
  release is bit-exact against the independent model. This record also
  covers everything record `20261008-235500-9e3008a` claimed (the
  framing, line-state and top-level suites, re-run here with unchanged
  assertions). One new parameterized test in
  `verification/test_usb_utmi_phy.py`,
  `test_tx_utmi_reset_aborts_and_recovers`, has 36 cases:
  9 phases × `Reset` held 1 or 3 clocks × `TxValid` low or held high
  during reset. Each case:
  1. Drives an aborted packet `[0x5A, 0xFF, 0x3C, 0xFC]`. It has an
     ordinary byte, a mid-byte stuffed 0 and the #7.1.9 trailing stuff
     bit.
  2. Checks that wire cells 0..c-1 match the model's SYNC + stuffed
     payload + SE0,SE0,J sequence. Cell `c`, the one the reset edge
     preempts, picks the phase: SYNC bit 4 (`sync`); SYNC's final bit
     (`sync_last`); byte 0 bit 3 (`payload`); the inserted mid-byte
     stuff 0 at run count 6 (`stuff`); the trailing stuff 0 (`flush`);
     the last level's own hold clock (`hold`); the second SE0
     (`eop_se0`); the EOP J (`eop_j`); the return to idle (`eop_idle`).
  3. Raises `Reset` after a falling edge. 1 ns later it checks that the
     in-flight cell and `TxReady` are unchanged (synchronous, not
     asynchronous).
  4. On every reset clock, checks that `txdp`/`txdm` are idle J and
     `TxReady` is high (the idle value from `test_reset_state`).
  5. Releases and sends `[0xFF, 0xFF, 0x00, 0xFC]` (sixteen leading 1s,
     two stuffed 0s, trailing stuff bit) through the normal handshake.
     The first byte must be accepted on the release edge itself if
     `TxValid` was held, or when offered (2 clocks later) if it was low.
     The post-release wire must equal idle J, then the model's complete
     SYNC + stuffed payload + SE0,SE0,J, then idle J, with nothing else.
     So no stale or duplicate byte, no malformed SYNC and no inherited
     stuffing run or NRZI reference. The looped-back RX path must
     receive exactly the fresh bytes, with no `RxError`.

  Injection coverage is checked from the ports, against the model. On
  the RTL run it is also confirmed by reading `tx_state` (and
  `stuff_consume` for the payload and stuff phases). These internal
  signals are read only to confirm coverage, never to supply an expected
  value. They are read only when the netlist exposes them at the RTL's
  width, so the gate-level replay skips them.
  - **Defect found and fixed.** On the RTL at `5e89df9` the new test
    failed 16 of 36 cases: `sync_last`, `payload`, `stuff` and `hold`,
    each under all four hold/`TxValid` variants. In every one, the wire
    changed from K to J *before* the sampling edge. Cause:
    `usb_nrzi_encoder` and `usb_bit_stuffer` (vendored) have an
    asynchronous reset port, which was fed `int_rst_n = rst_n & ~Reset`.
    That made `Reset` → `level_out` → `txdp`/`txdm` a combinational
    path while the TX state machine (synchronous) was still sending. The
    other 5 phases passed only because their in-flight cell was already
    J or forced by the EOP mux. The post-edge state and the recovery
    packet were already correct. Only the timing was wrong.
  - **Fix** (`rtl/usb_utmi_phy.v`, `spec/decisions/0005`). The two TX
    transforms' asynchronous port now takes `rst_n` only. While
    `int_rst_n` is low, `tx_clear` strobes them through their canonical
    inputs, so they clear on the sampling edge: the stuffer gets
    `bit_in` = 0, and the encoder gets `sof` with `bit_in` = 1 (idle J).
    No vendored byte changed (`reuse.lock.json` untouched). RX is
    unchanged (its asynchronous path is not port-visible; #132).
