# Record 20260817-184228-72de176

- **Claim**: `spec/usb2-device-phy.md` §11's digital signoff line -- "Digital
  UTMI-side logic (§2) verified by a cocotb testbench, bit-exact against
  NRZI/bit-stuffing/SYNC/EOP/line-state behavior" -- for the **rest** of
  §2/§4's digital logic beyond the bit-level codec (`bit-codec-functional`
  already covers that half): SYNC field detection and RX bit-lock, EOP
  (SE0) detection with the 2-bit-time-EOP-vs-2.5µs-reset disambiguation
  §4 requires, `LineState[1:0]` (J/K/SE0/SE1) decode from the two
  single-ended receiver outputs, and SYNC/EOP *generation* (TX), which
  live directly in the top-level wrapper's TX state machine rather than a
  dedicated module. It also claims the top-level `usb_utmi_phy` wrapper
  itself: the full UTMI port set of spec §3, assembled from this issue's
  three new modules plus the already-merged bit-level codec (issue #31),
  exercised end to end (TX byte-in → wire-level SYNC/NRZI/stuffed/EOP
  framed output; wire-level input → `DataIn`/`RxValid`/`RxActive` out via
  self-loopback). No claim is made here about synthesis, timing closure,
  or any electrical row of §4-§8; `LineState`/EOP detection are claimed
  only as digital logic against `line_state`/`rxdp`/`rxdm` inputs driven
  directly by the testbench, not against the analog receiver cells
  themselves.
- **Design provenance**: rtl (`rtl/usb_line_state_decode.v`,
  `rtl/usb_sync_detector.v`, `rtl/usb_eop_detector.v`, `rtl/usb_utmi_phy.v`,
  all new in this record; `rtl/usb_bit_stuffer.v`, `rtl/usb_nrzi_encoder.v`,
  `rtl/usb_nrzi_decoder.v`, `rtl/usb_bit_destuffer.v` unchanged since issue
  #31/PR #35, instantiated by `usb_utmi_phy.v`) @
  `72de176017de961f0ef220fd8fdae1965589aaa2`.
- **Run configuration**: `klt functional-verification` (engine `icarus`),
  four separate invocations because the request schema names a single
  `hdl_toplevel`:
  `verification/request-usb-line-state-decode.json`
  (`usb_line_state_decode` / `test_usb_line_state_decode`),
  `verification/request-usb-sync-detector.json`
  (`usb_sync_detector` / `test_usb_sync_detector`),
  `verification/request-usb-eop-detector.json`
  (`usb_eop_detector` / `test_usb_eop_detector`), and
  `verification/request-usb-utmi-phy.json`
  (`usb_utmi_phy` / `test_usb_utmi_phy`, which elaborates all eight RTL
  sources above in one run). Every request uses `options.random_seed` = 1,
  `options.timescale` = `["1ns", "1ps"]`, `options.coverage` = false, and
  no `testcase` filter (all tests in each module run). Every testbench
  clocks its DUT at 83334 ps, i.e. 12 MHz to within 0.001% -- the interface
  clock ratified in spec §3 and the raw full-speed bit rate, one bit per
  clock. Icarus Verilog 13.0, cocotb 2.0.1.
- **Statistical convention**: every case in this record is a directed,
  deterministic check (exact SYNC pattern, exact EOP/reset boundary
  clocks, exact TX SYNC/EOP wire shapes, a fixed set of TX byte payloads
  for the loopback round trips) rather than a randomized cross-check --
  N/A for a sample-size/seed beyond the fixed `options.random_seed` = 1
  every request carries for reproducibility of the (deterministic)
  simulation itself.
- **Result**:
  - `usb_line_state_decode`: 6/6 PASS (2083.350 ns total sim time)
  - `usb_sync_detector`: 7/7 PASS (11541.759 ns)
  - `usb_eop_detector`: 6/6 PASS (9666.744 ns)
  - `usb_utmi_phy`: 8/8 PASS (48500.388 ns)
  - **Totals: 27 tests, 27 passed, 0 failed, 0 skipped. Overall: PASS.**
  - `usb_line_state_decode`: reset-to-J, all four `LineState[1:0]`
    encodings (J/K/SE0/SE1) directly from `rxdp`/`rxdm`, and a toggling
    sequence across all four.
  - `usb_sync_detector`: the exact SYNC pattern pulsing `sync_valid` on
    precisely the eighth clock, a run of 1s (idle-J's own decoded shape)
    never matching, a corrupted bit inside an otherwise-correct pattern
    never matching, `enable` gating (re-enabling starts a fresh search
    rather than resuming a stale partial match), a `data_valid` gap
    holding the partial-match state, and a broken first attempt not
    preventing a clean second one.
  - `usb_eop_detector`: SE0 held for 1 clock (not EOP), held for exactly
    the 2-bit-time EOP boundary (`eop` pulses once and does not re-fire),
    held for one clock short of the 2.5µs/30-clock reset threshold
    (`bus_reset` never fires), held for exactly that threshold
    (`bus_reset` asserts on the boundary clock and stays asserted as a
    level until SE0 ends), and both outputs derived from a single long
    hold -- the exact EOP-vs-reset disambiguation-by-duration edge case
    this issue's test plan names.
  - `usb_utmi_phy`: reset state of every UTMI/wire-level port, the TX
    SYNC field's exact KJKJKJKK wire pattern, the TX EOP tail's exact
    SE0,SE0,J wire pattern, a single-byte TX→wire→RX self-loopback round
    trip, a multi-byte round trip that forces bit stuffing (cross-checked
    against `usb_bit_model.py`'s `bit_stuff`/`nrzi_encode`), a packet
    whose pre-stuff bit stream ends on exactly six 1s (USB 2.0 §7.1.9's
    mandatory trailing-stuff-bit case, exercising the wrapper's
    flush-before-EOP path), two packets sent back to back with the
    minimum possible inter-packet gap (`RxActive` provably drops between
    them), and a malformed/missing SYNC pattern that never asserts
    `RxActive`/`RxValid` (bit-lock failure fails safe) -- every edge case
    this issue's test plan named (SE0 held exactly at both boundaries,
    malformed SYNC, back-to-back packets with minimal gap) is covered and
    passing.
