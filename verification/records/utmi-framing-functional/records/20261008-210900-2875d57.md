# Record 20261008-210900-2875d57

- **Record ID**: 20261008-210900-2875d57
- **Claim**: characterization (issue #108) of whether `usb_utmi_phy`'s
  one-sample-per-bit, no-recovery RX path keeps `DataIn` bit-exact and
  `RxError` low when the host bit clock is independent of the device
  clock, the situation `spec/usb2-device-phy.md` §7 (12 MHz reference,
  +/-2500 ppm, unsynchronized to SOF) leaves open. **The §7-implied
  tolerance claim is NOT earned by this record: the measurement shows the
  RTL fails it.** The harness itself is verified (5/5 klt tests pass); the
  PHY result is a measured, recorded failure. This record does not edit
  the spec or the RTL; see `spec/decisions/0003-rx-bit-sampling-vs-clock-tolerance.md`.
  Not superseded by, and not superseding, the `20260922-004125-0446e4b`
  functional record (a different claim: synchronous behavior).
- **Design provenance**: `rtl/usb_utmi_phy.v` and its submodules @
  `2875d57` (unchanged by this issue; hashes in the metadata block).
- **Run configuration**: `USB_RXTOL_GRID=full USB_RXTOL_OUT=<matrix.json>
  klt functional-verification verification/request-usb-rx-clock-tolerance.json
  --format json`, engine `icarus` 13.0, cocotb 2.1.0 (throwaway venv
  supplying cocotb to the host klt; the host klt tool venv lacks cocotb),
  `random_seed` 1, timescale 1ns/1ps (simulator precision 1 ps), device
  clock period 83334 ps. Conventions: relative offset
  `ppm = 1e6*(f_host/f_dev - 1)`, host period `T_dev/(1+ppm/1e6)`
  (positive = host faster); absolute-deadline edges in exact rational
  arithmetic (<= 0.5 ps error per edge, none accumulated); phase k/8 of a
  device period after a DUT rising edge (phase 0 = coincident edge,
  scheduler-ordered, not claimed); frame = 8 idle J periods, unstuffed
  SYNC, payload-only stuffing incl. trailing stuff bit, SE0 x2 periods, J;
  pass = exact byte-for-byte `DataIn`, `RxActive` rose and fell, `RxError`
  never high. Grid: offsets 0, +/-1000, +/-2500, +/-5000 ppm and the exact
  opposing endpoint ratios 1.0025/0.9975 (+5012.531 ppm) and
  0.9975/1.0025 (-4987.531 ppm), 8 phases, patterns all-ones / all-zeros /
  seeded-mixed (seed 1), post-SYNC lengths 1/8/64/1024 bytes (9/74/597/9557
  stuffed wire bits for all-ones; 1024 bytes is an engineering stress
  length, not an asserted maximum USB packet size -- a full-speed
  isochronous packet is PID + up to 1023 payload bytes + CRC16 per USB
  2.0 as recalled, NOT verified against the standard here, and the PHY
  treats all bytes as opaque). 864 cases.
- **Statistical convention**: deterministic; no randomness beyond the
  seeded mixed payload. Repeating the full run produced a byte-identical
  matrix JSON.
- **Result**:
  - Harness (`npm test` legs): 5/5 PASS -- stimulus model (waveform decodes
    back to payload through the pure reference model; edges within 0.5 ps
    of the ratio-scaled grid at every offset; sign convention), scoreboard
    fault detection (corrupt, truncated, extra byte, missing SYNC, stuck
    `RxActive`, `RxError` each fail), missing-SYNC case terminates, zero-offset
    control at phase 1/2 matches every byte (all patterns, 1/8/64 bytes) and
    a +5% control fails, sweep complete (864/864 cases reported).
  - Tolerance matrix: **456 of 864 cases pass, 408 fail** (398
    `corrupt_byte`, 6 `extra_bytes`, 4 `truncated`). 295 of the 408 failures
    never asserted `RxError`; 113 did. Pass/fail was identical across the
    three payload patterns at every (offset, length, phase) point, i.e.
    the result is a function of accumulated slip against sampling phase,
    not payload content.
  - Per (offset, length), phases 0..7/8 left to right, `P` = all three
    patterns pass, `F` = all fail (no mixed points occurred):

    | offset (ppm) | 1 B | 8 B | 64 B | 1024 B |
    |---|---|---|---|---|
    | 0 | PPPPPPPP | PPPPPPPP | PPPPPPPP | PPPPPPPP |
    | +1000 | PPPPPPPP | PPPPPPPP | PFFFFPPP | FFFFFFFF |
    | -1000 | PPPPPPPP | PPPPPPPP | PPPPFFFF | FFFFFFFF |
    | +2500 | PPPPPPPP | PFPPPPPP | FFFFFFFF | FFFFFFFF |
    | -2500 | PPPPPPPP | PPPPPPPF | FFFFFFFF | FFFFFFFF |
    | +5000 | PFPPPPPP | PFFFPPPP | FFFFFFFF | FFFFFFFF |
    | -5000 | PPPPPPPP | PPPPPFFF | FFFFFFFF | FFFFFFFF |
    | +5012.531 (1.0025/0.9975) | PFPPPPPP | PFFFPPPP | FFFFFFFF | FFFFFFFF |
    | -4987.531 (0.9975/1.0025) | PPPPPPPP | PPPPPFFF | FFFFFFFF | FFFFFFFF |

  - Reading, within the sampled grid only: zero offset passes at every
    phase and length (control). Any nonzero offset tested fails at 1024
    bytes in every phase; every offset of magnitude >= 2500 ppm fails at
    64 bytes in every phase; the +/-5000 ppm class fails some phases even
    at 8 bytes (74 wire bits) and one phase at 1 byte. At +/-2500 ppm
    (§7's full tolerance on the host side alone, against a nominal device
    clock) 64 bytes already fails in every phase. Boundaries between grid points,
    and any continuous envelope, are not inferred. Mechanism consistent
    with the data: with a bit period equal to the sample period there is no
    margin to absorb slip, so roughly one wire bit is dropped (host fast)
    or repeated (host slow) per `1e6/|ppm|` bits, shifted by the starting
    phase. This is a digital-model result; it says nothing about analog
    metastability.
  - **Overall: harness PASS; PHY tolerance claim FAIL (measured).**
