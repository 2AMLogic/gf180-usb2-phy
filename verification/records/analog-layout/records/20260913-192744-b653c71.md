  5. **The four blocks' GDS output is geometrically stable but not
     byte-stable across this pin move, and this record originally
     mis-described how that was checked.** As first drafted, this record
     claimed the four artifacts were `cmp`-identical to the superseded
     record's. That claim was false and is corrected above (item 1) before
     this record merged — PR #74's review ran the comparison and found all
     four differ at the byte level. The substantive conclusion survives (the
     geometry is provably unchanged, item 1), but the method the record
     credited did not produce the result it reported, which is exactly what
     `CLAUDE.md`'s "no claim without a testbench" exists to catch; the
     corrected claim names the method that was actually run.

     What the byte difference actually is, characterized directly rather
     than assumed: decoding both files' raw GDS record streams shows the
     library-level header records (`HEADER`, `BGNLIB` — which carries GDS's
     modification/access timestamps — `LIBNAME`, `UNITS`) are **identical**
     in all four pairs, so this is *not* a timestamp artifact; total record
     counts and the whole record-type sequence are identical; file sizes are
     identical to the byte; and the **multiset of elements is identical**
     (159, 1531, 180, 180 elements respectively, comparing each
     boundary/path/sref/text element canonically by owning structure plus
     every one of its sub-records, `LAYER`/`DATATYPE`/`XY` included — zero
     elements present in one file and absent from the other). The sole
     difference is the *order* in which the same elements are emitted within
     a structure: in `differential_receiver` exactly two boundaries swap
     position (a `110/5` and a `31/0`), while `dplus_pullup` is a broader
     permutation (1110 of 8114 records land at a different offset). No
     coordinate, layer, datatype, or cell-structure value changed anywhere —
     which is why the XOR area is zero.

     **Not filed upstream by this record, deliberately.** Unstable emission
     order does defeat byte-level artifact comparison, which this repo's
     evidence discipline would otherwise like to lean on — but two artifacts
     produced at two *different* pins cannot distinguish "`klt`'s writer
     changed its ordering between these two versions" (a behavior change,
     arguably benign) from "`klt`'s writer is nondeterministic run-to-run at
     a fixed version" (a reproducibility bug worth a friction filing). This
     run does not have the repeat-execution-at-one-pin evidence needed to
     tell those apart, and manufacturing it is out of scope for issue #72.
     Recorded here as an observation with its reproduction so that a future
     run at a fixed pin can settle it and file if warranted.
