- **Result**:

  **1. Cause, measured.** The byte order of a plan's stream depends on what ran before it in the same interpreter. Measured directly against klt's executor, with none of this repo's generator involved -- no scripted routing, no `lpe.compose` monkeypatch, just two `execute_layout_plan_document()` calls -- the `dplus_pullup` plan's own klt output differs between "executed alone in a fresh process" (`8a0eb121...`) and "executed after one sibling plan in the same process" (`13c9f420...`). Those two klt outputs hold the same 49 structures and the same 2026 element blocks, with **18 structures differing only in element order and 0 differing in content**. So the leaked state is inside klayout-tools (or the `klayout.db` it writes through), **not** in this script: filed generically as `2AMLogic/klayout-tools#5499`, which the maintainer of `2AMLogic/klayout-tools#5489` had invited on exactly this evidence. Before the fix, `dplus_pullup` reproduced its recorded `c4080adb...` under one selection only -- `--check --blocks differential_receiver dplus_pullup` -- and `3729bd19...` under every other, which is why it broke at `6b6483e` when `differential_driver` began executing ahead of it.

  **2. Fix, and what it makes true.** `main()` now executes each plan in a child interpreter (`_execute_plan_isolated`) whenever a run has more than one plan, and merges the per-block entries; a lone plan already owns its interpreter and runs in-process.
