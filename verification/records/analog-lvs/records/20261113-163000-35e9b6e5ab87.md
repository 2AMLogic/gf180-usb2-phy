### What each cause looks like now

Read off `<block>-cause.json`, which `scripts/analog_lvs.py` regenerates on
every run, exactly as the superseded record's cause tables were.

**Cause A -- PMOS bodies.** `bulk_nets.layout` equals `bulk_nets.reference`
on every block: `pfet` -> `VDD` on the four `VDD` blocks and `VPU_REG` on
`dplus_pullup`. No PMOS body sits on an anonymous well net on any block.

**Cause B -- the substrate.** `vsubs` does not appear in any of the five
extracted layout netlists (`grep -c vsubs <block>_layout.spice` is 0 on all
five), and `bulk_nets.layout.nfet` is `VSS` on every block. The reference
puts them on `VSS` too. The deck-synthesized substrate net is now named and
is no longer exported as a top-level pin.

**Cause C -- the port set.** `ports.only_in_layout` and
`ports.only_in_reference` are both `[]` on all five blocks; the layout pin

### What this run compared, and what it did not

**It did compare MOS geometry.** With every device paired, KLayout's
primary MOS parameters (`L`, `W`) took part in the compare on all five
blocks and agreed within the engine's default tolerance -- no
`parameter_tolerance` and no `compare_parameters` override were set.
`device_parameter_coverage` lists no `nfet`/`pfet` entry on any block,
which is the report's way of saying nothing was excluded for those classes.
This is new: the superseded record could say nothing at all about drawn
sizes, because with near-zero device pairing no W/L comparison took place.

**It did not compare resistor geometry.** `device_parameter_coverage`
reports, per block, that every parameter of the poly-resistor classes was
excluded: `R` as `placeholder_value` (a `subckt-call` reference carries the
literal 0 placeholder; klt has no sheet-resistance data to compute a real
one) and `L`/`W`/`A`/`P` as `secondary` (KLayout compares primary
parameters only). The two warnings `device.geometry_not_compared` and
`device.placeholder_value` say so on every block, once per resistor class
(`ppolyf_u_1k` on the three receivers; `ppolyf_u` and `rm1` on
`differential_driver`; `ppolyf_u` on `dplus_pullup`). **The poly resistors
therefore paired on topology alone, and this record does not verify their
drawn dimensions.** In particular the five `dplus_pullup` trim resistors
whose drawn lengths deviate from the netlist by operator ruling DR-0010
(`spec/decisions/0010-dplus-pullup-trim-resistor-grid-snap.md`) would not
have been caught here either way. That limitation is unchanged from the
superseded record and is not something this issue's work altered.

A third warning, `topology` (one per block), reads "device class has no
counterpart on the other side, but no devices of this class were extracted
either -- not a real topology mismatch: 'bjt'". It is informational: the
deck declares a `bjt` class that neither side uses.

### What is NOT established

- **ERC, and any extracted re-simulation.** Neither was run. A match says
  the drawn connectivity is the schematic's; it says nothing about supply
  integrity (#248) or post-layout behaviour (#53).
- **Resistor dimensions**, per the paragraph above.
- **That the tie geometry is the one a signoff reviewer would draw.** Each
  body is tied through exactly one of the generator's own contacted tap
  pads per device group, because a group's pads already share one well (or
  the one substrate). That is sufficient for extraction and for DRC's
  tap-distance rule, both measured. It is not an IR-drop or
  latch-up-margin argument, and no such claim is made.
- **Anything about the four blocks' analog performance.** No electrical
  measurement is in this record.
