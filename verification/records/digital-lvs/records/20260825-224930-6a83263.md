# Record 20260825-224930-6a83263

- **Record ID**: 20260825-224930-6a83263
- **Claim**: **gate-level LVS on the digital PHY is a match** — the routed
  GDS `layout/digital/usb_utmi_phy.gds` instantiates exactly the standard
  cells the as-built gate-level netlist
  `layout/digital/usb_utmi_phy_routed.v` names, wired to exactly the same
  nets, with the same top-level pin set. This is the T1 checklist's
  LVS-matched signoff item for the digital half. It is the first LVS record
  of any kind in this repo (the prior P&R and DRC records both state
  plainly that LVS was **not attempted**).
- **Design provenance**: layout (post-P&R, **extracted**) vs. netlist
  (post-P&R as-built, `write_verilog` — CTS buffers, resizes and antenna
  repair included). The as-built netlist, not `klt synthesize`'s pre-CTS
  one, is the correct reference here: it is the only netlist that names the
  clock tree the layout actually contains, and `klt place-and-route`'s own
  contract says so.
- **Run configuration**:
  ```
  PDK=gf180mcuD python3 scripts/digital_lvs.py
  PDK=gf180mcuD python3 scripts/digital_lvs.py --negative-control
  ```
  That script (committed, re-runnable, documented in its own module
  docstring) drives two `klt` 0.3.0 commands:
  - **layout side** — `klt extract … --deck gf180mcu --top usb_utmi_phy
    --def-net-names --top-cell-pins --pins <35 ports + VDD + VSS>` with one
    `--abstract-cells <cell>` per **logic** cell type (55 of them) and
    `--abstract-cell-lef` pointing at the resolved PDK's
    `gf180mcu_fd_sc_mcu9t5v0.lef`. Holding the logic cells as black boxes is
    what makes this a **gate-level** compare; `--def-net-names` is what
    recovers the design's own net names (`_111_`, `u_destuffer/ones[2]`)
    from the DEF merge instead of KLayout's `$<id>` placeholders.
  - **reference side** — a SPICE transcription of the as-built Verilog
    generated by the same script: one empty `.SUBCKT` per logic cell type,
    one `X` card per instance. Every connection is mapped **by pin name**
    from the Verilog's own named port connections; only the column *order*
    is taken from the extracted netlist, because SPICE has no named-port
    syntax and both sides must agree on one. An ordering borrowed from the
    layout cannot mask a wiring difference — it would surface as a
    mismatch, which is precisely what the negative control below
    demonstrates.
  - **compare** — `klt lvs` with `engine: "klayout"`
    (`klayout.db.NetlistComparer`), no `parameter_tolerance`, no
    `combine_devices`, no flattening.
- **Statistical convention**: N/A — a single deterministic compare of a
  fixed netlist pair, plus one deterministic negative control.
- **Result**:
  - **`status: "match"`, `mismatch_count: 0`, `error_count: 0`,
    `category_counts: {}`.**
  - Counts: nets layout 373 / reference 373; pins layout 37 / reference 37;
    devices 0 / 0 (by construction — every transistor is inside an
    abstracted cell, so the compare is over subcircuit instances and net
    topology, not devices).
  - Inventory reconciled by the run: 352 logic instances across 55 cell
    types on both sides; 35 top-level RTL ports plus `VDD`/`VSS`.
  - **Negative control — the reason this "match" is evidence rather than a
    tautology.** `--negative-control` regenerates the same reference with
    exactly one connection deliberately broken (the first instance's first
    non-supply input rewired to `VSS`) and requires `klt lvs` to reject it.
    It does: `status: "mismatch"`, one `category: "topology"`,
    `severity: "error"` entry — "subcircuit instance could not be matched to
    a counterpart". A harness that reported "match" on both inputs would be
    measuring nothing; this one does not.
  - **Overall: pass.**
- **Three real asymmetries between the two sides, and how each is handled**
  (each is a fact about the flow, not a fudge — all three are resolved in
  the script, in the open):
  1. **Physical-only cells.** The routed layout contains 854 `fill_*` /
     `endcap` / `filltie` instances that the power stage inserted and that
     the as-built Verilog correctly does not name. They are deliberately
     *not* abstracted, so extraction flattens them; they contain no
     transistors, contribute `device_count: 0`, and therefore drop out of
     the compare entirely rather than being explained away.
  2. **Unconnected CTS load pins.** CTS instantiates dummy `clkload*`
     inverters with only their input tied (`.ZN()` absent). The reference
     gives each such pin its own named dangling node, so it stays a
     one-terminal net exactly as the isolated pin shape extracts — rather
     than being tied to a shared node, which would silently short several
     of them together.
  3. **`assign`-aliased output ports.** Yosys emits `assign LineState[0] =
     line_state[0];`, and OpenROAD writes the DEF net under the *driver's*
     name with the port hung off it as a `PIN`. The extracted net is
     therefore `line_state[0]`, not `LineState[0]`; the script resolves each
     port through its alias before comparing, and *fails loudly* if the two
     sides' top-level pin sets differ as sets.
- **Scope of the claim** (what a match here does *not* say):
  - **The standard cells themselves are not verified.** They are black
    boxes: the foundry's own characterized GDS is taken as correct. This
    record checks the *assembly*, not the library. A transistor-level LVS
    of the same layout is a strictly stronger, and separate, claim.
  - It says nothing about the analog blocks — no analog GDS is committed.
  - It says nothing about timing or electrical behaviour, and it is not a
    post-layout (extracted-parasitic) simulation.
  - `provenance.pdk` is recorded because the run resolves the cell
    library's LEF from the PDK install; the compare engine itself has no
    PDK dependency.
