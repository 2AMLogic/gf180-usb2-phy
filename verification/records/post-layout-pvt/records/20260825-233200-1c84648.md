  (`layout/digital/usb_utmi_phy.gds` / `.def`) is timed with a

- **Result**:
  - **Extraction**: `status: "extracted"`, 4302 devices, 2037 nets (flat).
    First attempt (`--parasitics --spef`, no `--def-net-names`) produced a
    SPEF whose declared net names are KLayout's own synthesized/anonymous
    labels; feeding that into `klt sta` correlated only **5 of 366** design
    nets (`spef_annotation.design_nets_annotated`). Re-run with
    `--def-net-names --def-net-connections
    layout/digital/usb_utmi_phy.def` (which recovers the DEF's own net
    names via the GDS net-name property KLayout's LEF/DEF reader
    records) raised that to **186 of 366** — the SPEF/run frozen under
    this record's `artifacts/` is the `--def-net-names` one.
  - **Net-name correlation, characterized (not just reported)**: an
    independent check against the raw DEF `NETS` section (364 signal nets)
    plus the two power/ground special nets (366 total, matching
    `spef_annotation.design_nets_total`) shows this is not a soft/partial
    mismatch but a **clean binary split**: every one of the **184
    plain-named** signal nets (e.g. `Reset`, `TxValid`, `_123_`) correlates;
    every one of the **180 nets whose DEF name contains a bus-index
    bracket or a hierarchical-path slash** (e.g. `DataIn[3]`,
    `u_stuffer/_11_`) does not — 184 + 2 (`VDD`/`VSS`) = **186**, exactly
    the tool's own reported count. This is despite those 180 names being
    present, correctly SPEF-escaped (`DataIn\[3\]`, `u_stuffer\/_11_`), in
    the SPEF's own `*D_NET`/`*PORTS` blocks — unescaping them by hand
    against the raw DEF net list finds **362 of 364** structurally
    matching by name. The 186/366 vs. 362/364 gap looks like a
    correlation-side defect in how `klt sta`'s net-name lookup
    handles SPEF-escaped `[`/`]`/`/` characters, not a defect in the
    extracted SPEF's own net-name content — see "Friction filed" below.
  - **Timing, all three corners** (SPEF-annotated vs. this design's own
    prior liberty/estimated-RC record, `20260825-224709-6a83263`, same
    corners):

    | Corner | SPEF-annotated worst setup slack | Liberty/estimated-RC worst setup slack | Delta |
    |---|---|---|---|
    | `tt_025C_1v80` (nominal) | 69.9786 ns (`fmax` 74.8814 MHz) | 68.7478 ns (`fmax` 68.53 MHz) | +1.2308 ns |
    | `ss_125C_1v62` (worst setup corner) | 50.2482 ns | 47.286 ns | +2.9622 ns |
    | `ff_n40C_5v50` (worst hold corner) | 80.93 ns | 80.7117 ns | +0.2183 ns |

    `setup_violation_count`/`hold_violation_count` are 0 at all three
    corners, consistent with the liberty-only record. `klt sta`'s response
    schema reports hold as a violation **count**, not a slack value, so no
    hold-slack delta number exists to report here — a genuine schema gap
    for this comparison, not an omission.
  - **Overall: not a pass/fail claim.** Every corner's SPEF-annotated
    number moved in the same (less-pessimistic) direction relative to its
    liberty baseline, by a small amount (+0.22 to +2.96 ns on setup slack)
    — but with only 186/366 design nets carrying real extracted parasitics
    and the rest falling back to OpenSTA's own LEF-capacitance estimate,
    this table is **not** the "real-parasitics measurement" #51/#53 ask
    for. It is the honest result of the attempt: real numbers, real
    annotation-coverage math, and a named, evidenced root cause for why
    coverage is partial — recorded per this repo's rule against claiming
    more than the evidence supports.
  - **Estimated power**: 0.1354 mW / 0.1129 mW / 1.3763 mW at
    `tt_025C_1v80` / `ss_125C_1v62` / `ff_n40C_5v50` respectively (the
