# Record 20261115-105609-c973e30

- **Record ID**: 20261115-105609-c973e30
- **Claim**: a drawn-geometry check — **not** a resistance claim, **not** an LVS
  verdict, and **no** simulation — now covers every resistor device in all five
  committed analog streams (`layout/analog/*.gds`): each resistor's drawn
  `L`/`W`, read off the GDS resistor-marker layer, is compared exactly against
  the netlist's `r_length`/`r_width` from `design/netlist/<block>.spice`. On
  the streams pinned above the result is **19/19 devices accounted for: 14
  exact matches, 5 deviations, every one of them one of the five
  `dplus_pullup` trim segments sanctioned by DR-0010 and drawn at exactly the
  length that decision record allows, and 0 findings**. No resistor, plan, GDS
  or spec was changed by this issue; the check, its unit test and this record
  are the only additions.
- **Design provenance**: git `c973e30` (`origin/main`; the record is minted on
  the commit that adds it, so this revision is the parent). The five streams
  are the current delivered set — every `provenance.inputs[].content_hash`
  above equals the working-tree `sha256` *and* the block's recorded
  `gds_sha256`/`plan_sha256`/`netlist_sha256` in
  `layout/analog/provenance.json` (the check refuses to measure anything
  unless `scripts/check_analog_provenance.py`'s contract passes first, so the
  measurement cannot silently describe a drifted stream). The generator of
  record is `scripts/gen_analog_layout.py --deliver`; LVS topology, DRC and
  ERC measurement of these streams live in the `analog-lvs`, `analog-drc` and
  `analog-erc` records respectively.
- **Run configuration**: one pass of
  `python3 scripts/check_analog_resistor_dims.py` in a throwaway
  `uv run --no-project --with klayout==0.30.13` environment (the same klayout
  version CI's `klayout-tools==0.9.0` pin resolves), exit 0, with
  `--json` writing the machine-readable report frozen as this record's
  artifact. The check joins each netlist resistor `XR<NAME>` to the plan
  `res_array` group whose device name is `<NAME>` (all groups
  `num: 1, dummy: 0`, all instances `m=1` — anything else is a fail-loud
  error), then to the GDS cell `<group_id>__<group_id>_0`, and reads the
  bounding box of the resistor-marker layer (`110/5` for `PPOLYF_U`/
  `PPOLYF_U_1K`, `110/11` for `RM1`) inside that cell — a region whose extent
  is exactly the drawn `L` × `W`, with no overhead constant. **Grid note
  (correction to the issue's curation)**: the curation measured
  `dbu == 0.001` on all five streams as of `cac61d7`; the delivered streams
  above are on a **0.5 nm grid (`dbu == 0.0005`)** — the streams moved with
  the regeneration the `analog-lvs`/`analog-drc` records pin — so raw
  database units no longer mean the same thing across streams. The check
  therefore compares **whole nanometres** (exact integers; identical integers
  to dbu on the old 1 nm grid), and a dimension that is not a whole number of
  nanometres on its stream's grid is a fail-loud error, never a rounded pass.
  Negative controls, all run against the real streams, none committed: (a)
  perturbing the allow-list to claim `XR0` is allowed at 0.345 µm makes the
  script exit 1 naming `XR0` as `FAIL (allow-list)`; (b) dropping the `XR4`
  entry makes its real deviation exit 1 as `FAIL`; (c) flipping one byte of
  `dplus_pullup.gds` makes the provenance contract refuse the measurement,
  exit 2 (`gds_sha256 is stale`); (d) blanking the `110/5` geometry under
  `r_seg0__r_seg0_0` (it lives in the `r_seg0_0__core` child cell) makes the
  script exit 2 naming the cell, rather than reporting a zero; (e) on a bare
  `python3` with no klayout module the script exits 2 with the
  `./scripts/setup-env.sh` message.
- **Statistical convention**: none applies. This is a deterministic geometry
  read at a single point — there is no distribution, no corner and no sample
  count; every number below is an exact equality or a recorded difference.
