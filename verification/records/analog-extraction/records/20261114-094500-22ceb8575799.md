### The failure mode is silence, and that is the finding worth carrying

`klt extract` writes `.SUBCKT differential_receiver DM DP RXD VDD VSS`
(alphabetical). `design/netlist/differential_receiver.spice` declares
`.subckt differential_receiver VDD VSS DP DM RXD`, and
`sim/diff-receiver-sensitivity/testbench/diff_rx_tb.spice:65` instantiates
`Xrx1 VDD 0 DP1 DM1 RXD1 differential_receiver` — **positionally**. The two
port lists are the same five names in a different order, so SPICE binds
`VDD→DM`, `VSS→DP`, `DP→RXD`, `DM→VDD`, `RXD→VSS`.

ngspice does not complain. It emitted **no error and no warning**, converged,
and produced the middle column above: a ±500 mV threshold that reads like a
real sensitivity failure and output levels near mid-rail that read like a real
drive-strength problem. Nothing in that output says "mis-wired". Had this run
been taken as the post-layout result, the honest-looking conclusion would have
been that the laid-out receiver fails spec §4 — a layout-performance verdict
read off a wiring artifact. **Any future extracted re-run (#53) must assert
the port order rather than assume it**, because the failing mode of getting it
wrong is a plausible number, not a crash.

### The reconciliation, in full

On the pinned klt nothing reorders the header: `--pins` is a per-net promotion
*filter* (verified — passing `--pins VDD,VSS,DP,DM,RXD` to klt 0.9.0 still
writes `DM DP RXD VDD VSS`), `--top-cell-pins` is a per-cell filter, and
`--rename-declared-pins` renames without reordering. The port *names* already
agree and SPICE binds by name *inside* a subcircuit, so permuting the single
`.SUBCKT` header line is a complete and sufficient fix — the body is untouched:

```
16c16
< .SUBCKT differential_receiver DM DP RXD VDD VSS
---
> .SUBCKT differential_receiver VDD VSS DP DM RXD
```

That is the whole adaptation, frozen as `pin-order-adapter.diff` and
reproducible with one `sed` (see Replay). Both files are committed so the diff
is auditable: `differential_receiver_parasitic.spice` is klt's output
byte-for-byte, and `differential_receiver_parasitic_reordered.spice` is the
simulated DUT. **No hand-edit of device cards, parameters, or connectivity was
made, and none is hidden in the reorder.**

**Control, and the reason this is not a hand-fudge.** The newer host klt
(`0.9.2.dev1029+g76f47afa48f1`) *does* honour `--pins` as a header ordering:
given `--pins VDD,VSS,DP,DM,RXD` it writes
`.SUBCKT differential_receiver VDD VSS DP DM RXD` directly. Its output is
**byte-identical** to the pinned klt's output plus the one-line `sed`
(`diff` is empty). So the adaptation is provably exactly what the tool itself
now does — and, incidentally, nothing else in this netlist moved between klt
0.9.0 and 0.9.2.dev1029.

### Both pre-identified device-carding blockers were avoided by `--pdk`

The curator's analysis of the *existing* device-level extract (the one
`scripts/analog_lvs.py` freezes under `analog-lvs/`) predicted two further
blockers, and both are real for that file — but both are artifacts of how that
harness invokes the tool, not of extraction:

1. **Undefined device models.** `scripts/analog_lvs.py:314` runs `klt extract`
   with no `--pdk`, which writes bare `M$1 ... nfet` cards. `nfet` is not
   defined anywhere in the harness's `model_lib`
   (`~/.volare/gf180mcuD/libs.tech/ngspice/sm141064.ngspice`) — only
   `.subckt nfet_03v3` is. `klt extract --help` on the pin states it: *"Omitted,
   MOS devices are written as bare M cards … pass `--pdk` for the
   subckt-wrapper X call."* With `--pdk gf180mcuD` the devices come out as
   `X$1 \$6__t2 \$8__t1 VSS__t1 VSS__t5 nfet_03v3 L=0.28U W=2U …`, against the
   subcircuit the deck does define.
2. **Resistor parameter names.** The same flag fixes the poly resistor: it is
   written `X$11 \$5__t3 VDD__t6 VSS__t4 ppolyf_u_1k r_length=400U r_width=2U`
   — the parameter names `.subckt ppolyf_u_1k 1 2 3 r_length=l r_width=w …`
   actually declares, not the `r=/L=/W=` form the no-`--pdk` output used.

So of three predicted blockers, two dissolve with one flag and only the port
order needed adapting. Worth noting for #53: **`--pdk` is required for a
simulatable extraction**, and the LVS harness does not pass it (correctly —
LVS does not need it).

### What the extraction models, and what it omits

Read off the pin's own `--help`, the netlist's self-describing header, and the
report's `parasitics.model` block (`model_revision: 2`) — not inferred:

**Modelled.**
- **Resistance**: one lumped series R per net, distributed as a **star** across
  that net's device terminals (`rc_model: "lumped"` on all 10 nets). 43 R cards,
  967.2993 Ω total. Per-net: `\$5` 318.5 Ω, `\$8` 140.3 Ω, `\$6` 124.6 Ω, `VDD`
  113.6 Ω, `\$7` 110.7 Ω, `VSS` 51.5 Ω, `DM`/`DP` 30.9 Ω each, `\$4` 29.3 Ω,
  `RXD` 17.2 Ω — attributed per layer (`poly`, `metal0`, `metal1`, `metal2`).
- **Capacitance to ground**: 10 C cards, 164.134034 fF total, from each net's
  own non-coupled area/perimeter.
- **Coupling capacitance**: **vertical overlap only**, 24 `Ccc_*` cards,
  0.457938 fF total, charged between the two nets' hub nodes.
- Values come from the deck's curated sheet-resistance/capacitance table, with
  `metals_without_coefficient: []` and `overlap_pairs_without_coefficient: []`
  — i.e. no geometry was skipped for want of a coefficient. The report's own
  `integrity` block self-checks clean: 10 nets checked, 0 findings, 0 open
  nets, 0 islands, 0 orphan nodes, 0 short candidates, 0 capacitance
  mismatches.

**Omitted — and this is the half that matters for reading the numbers.**
- **Lateral (same-layer, sidewall) coupling**: not modelled at all here.
  It is emitted only for a net pair naming a `--critical-net`, and
  `critical_nets: []`. Every `coupled[].lateral_levels` is empty. Fringe
  shielding is not modelled in general.
- **Distributed RC**: `distributed_rc: false`, every `segments: []`. The star
  hub is not a ladder, so intra-net delay ordering along a wire is not
  represented.
- **Substrate**: capacitively floating. The substrate net `vsubs` is tied to
  ground through `Rvsubs_dctie vsubs 0 1e+12` — a 1 TΩ DC reference only
  (`substrate_dc_tie.mode: "shunt"`). **No substrate spreading resistance**
  (`substrate_spreading: null`; it requires `--substrate-spreading`, and even
  then is a Kelvin two-disc *estimate*, not an N-terminal solve). No well
  network.
- **Inductance**: none. `l_count: 0`, `total_inductance_nh: 0.0`,
  `mom_rlc_override: null`.
- **Field-solver cross-check**: none. `mom_crosscheck: null` (`--mom-net` not
  used), so every capacitance is the deck's lumped-RC coefficient, not a
  Method-of-Moments result.
- **Frequency dependence**: none — quasi-static, one frequency-independent R
  and C per net; no skin effect, no transmission-line behaviour.

One extraction warning, unrelated to parasitics and identical to the
analog-LVS run's: the deck declares MOS flavour `06v0` scoped by marker layer
55/0, that layer has no shapes, so every MOS binds to the deck's default
flavour. Also recorded for honesty: the report's
`provenance.pdk.compatibility.status` is **`mismatch`** — klt expects
open_pdks `f6eeac7dad08...` and the repo pins `c6d73a35f524...`. That is the
repo's standing pin, unchanged by this issue and the same pairing every
analog record to date has run under.

### What this probe does NOT establish

- **That the parasitics are electrically immaterial.** The reconciled run
  matches the schematic on all three thresholds *exactly* (−21 / −24 / −27 mV),
  and the only movement is in the three `lo_*` levels (2.608e−10 → 2.741e−10,
  2.610e−10 → 2.745e−10, 3.059e−10 → 3.429e−10 — sub-nanovolt leakage floors).
  **This is expected and is not evidence of a parasitic-insensitive design**:
  `tb.json`'s only analysis is `dc vsw -0.5 0.5 0.001`, a DC sweep. At DC a
  capacitor is an open, so the 164 fF of ground capacitance and 0.458 fF of
  coupling **cannot affect the result at all**; the entire observable delta is
  the series R. Any claim about what layout parasitics do to this receiver
  needs a transient or AC analysis, which this experiment does not contain.
- **Anything at the other 44 corner points**, or for the other four streams.
  One point (`tt_27c_3.30v`), one block, by design (#53 owns the matrix).
- **That the extracted netlist is LVS-correct in this parasitic form.** The
  LVS match cited above is of the *device-level* extract of the same stream.
  This record does not re-run LVS on the parasitic-annotated file.
- **Nothing was re-verified about `sim/spec-coverage.md`**, which is unchanged
  (AC #5) — its rows remain schematic-netlist measurements.

## Friction: already filed upstream, and already fixed after our pin

Per this repo's friction protocol the port-order gap is the one filing-worthy
item here — and it is **already on the klayout-tools tracker, so no duplicate
was filed**:

- [`2AMLogic/klayout-tools#2890`](https://github.com/2AMLogic/klayout-tools/issues/2890)
  (closed) — *"extracted `.SUBCKT` pins are written alphabetically, but a
  testbench instantiates its DUT positionally; no reconciliation or
  diagnostic"*. That is precisely this failure, including the absence of a
  diagnostic.
- [`2AMLogic/klayout-tools#5255`](https://github.com/2AMLogic/klayout-tools/issues/5255)
  (closed) — *"`--pins` does not control extracted subcircuit pin order"*. The
  fix for this is what the host klt demonstrates above; it landed **after**
  `0.9.0`.
- [`2AMLogic/klayout-tools#5534`](https://github.com/2AMLogic/klayout-tools/issues/5534)
  (**open**) — the remaining edge in that fix: `--pins` header ordering hoists
  only whole-name matches, so a joined-label layout's port order can still
  move between builds. Not triggered by this block (single-label nets), but it
  is the live tail of the same gap.

**Actionable consequence for this repo, not filed upstream**: the gap is a
*pin-version* problem for us, not an unmet tool capability. A `klt` pin bump to
a release carrying #5255's fix would let #53 pass `--pins VDD,VSS,DP,DM,RXD`
and drop the `sed` adapter entirely. Bumping the pin is out of scope here
(it would re-base every existing analog record's provenance), so it is left as
a recommendation attached to #53 rather than done silently.
