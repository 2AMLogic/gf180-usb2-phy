# Record 20260816-074908-4e92fcc

- **Record ID**: 20260816-074908-4e92fcc
- **Claim**: `spec/usb2-device-phy.md` §11's digital signoff line -- "Digital
  UTMI-side logic (§2) verified by a cocotb testbench, bit-exact against
  NRZI/bit-stuffing/... behavior" -- for the **bit-level half** of §2: NRZI
  encode (TX), NRZI decode (RX), bit stuffing (TX, a 0 after every six
  consecutive 1s, *including* the trailing bit USB 2.0 §7.1.9 requires when
  a packet ends on six 1s), and bit destuffing (RX, including a bit-stuff
  error on seven consecutive 1s). §2's SYNC/EOP and `LineState[1:0]`
  clauses are **not** claimed by this record; that logic does not exist yet
  and will need its own record. No claim is made here about synthesis,
  timing closure, or any electrical row of §4-§8.
- **Design provenance**: rtl (`rtl/usb_nrzi_encoder.v`,
  `rtl/usb_nrzi_decoder.v`, `rtl/usb_bit_stuffer.v`,
  `rtl/usb_bit_destuffer.v`, all @
  `4e92fcc33b0c879662a083ea8dcd2511e7550dee`). The RTL-to-RTL round-trip
  leg additionally elaborates `verification/tb_usb_bit_codec_loopback.v`,
  which is testbench scaffolding rather than design source -- it contains
  no logic of its own, only the four instances above and the wires between
  them.
- **Run configuration**: `klt functional-verification` (engine `icarus`),
  five separate invocations because the request schema names a single
  `hdl_toplevel`:
  `verification/request-usb-nrzi-encoder.json` (`usb_nrzi_encoder` /
  `test_usb_nrzi_encoder`),
  `verification/request-usb-nrzi-decoder.json` (`usb_nrzi_decoder` /
  `test_usb_nrzi_decoder`),
  `verification/request-usb-bit-stuffer.json` (`usb_bit_stuffer` /
  `test_usb_bit_stuffer`),
  `verification/request-usb-bit-destuffer.json` (`usb_bit_destuffer` /
  `test_usb_bit_destuffer`), and
  `verification/request-usb-bit-codec-loopback.json`
  (`tb_usb_bit_codec_loopback` / `test_usb_bit_codec_loopback`). Every
  request uses `options.random_seed` = 1, `options.timescale` =
  `["1ns", "1ps"]`, `options.coverage` = false, and no `testcase` filter
  (all tests in each module run). Every testbench clocks its DUT at
  83334 ps, i.e. 12 MHz to within 0.001% -- the interface clock ratified in
  spec §3 and the raw full-speed bit rate, one bit per clock. Icarus
  Verilog 13.0, cocotb 2.0.1.
- **Statistical convention**: the randomized cross-checks draw from fixed,
  per-testbench `random.Random` seeds so every run is reproducible:
  `test_usb_nrzi_encoder.test_random_stream_matches_model` (seed 20260816,
  512 uniform bits), `test_usb_nrzi_decoder.test_random_stream_round_trips`
  (seed 20260817, 512 uniform bits),
  `test_usb_bit_stuffer.test_random_stream_matches_model` (seed 20260818,
  512 bits drawn 80% 1s so stuffing actually fires -- a uniform stream
  almost never produces a six-long run of 1s),
  `test_usb_bit_destuffer.test_random_stream_round_trips` (seed 20260819,
  512 bits, same 80% bias), and
  `test_usb_bit_codec_loopback.test_round_trip_random_stream` (seed
  20260820, 512 bits, same 80% bias). Every other test is a directed,
  deterministic check; N/A for an overall sample size beyond the above.
- **Result**:
  - `usb_nrzi_encoder`: 6/6 PASS (50250.402 ns total sim time)
  - `usb_nrzi_decoder`: 6/6 PASS (50583.738 ns)
  - `usb_bit_stuffer`: 9/9 PASS (65875.527 ns)
  - `usb_bit_destuffer`: 9/9 PASS (57292.125 ns)
  - `tb_usb_bit_codec_loopback`: 5/5 PASS (64042.179 ns)
  - **Totals: 35 tests, 35 passed, 0 failed, 0 skipped. Overall: PASS.**
  - Every randomized case is bit-exact against `verification/usb_bit_model.py`,
    an independent Python reference written from the prose rules in spec §2
    that shares no structure with the RTL (no clocks, no valid strobes, no
    pipeline latency).
  - The edge cases this issue's test plan named are all covered and
    passing: all-1s input (maximal stuffing density, and never more than
    six 1s emitted consecutively), all-0s input (no stuffing at all),
    stuff-error injection (seven consecutive 1s raises a one-clock
    `stuff_err`, re-raised at every subsequent stuff position in a longer
    1 run), and NRZI decode of a transition-free line (which correctly
    yields a run of 1s rather than an error).
  - The packet-boundary case USB 2.0 §7.1.9 governs ("a zero bit will be
    inserted even if it is the last bit before the end-of-packet (EOP)
    signal") is covered in all three places it can be observed:
    `test_usb_bit_stuffer.test_trailing_run_of_six_is_stuffed_on_flush`
    (the flushed stuffer emits the trailing 0 while consuming exactly six
    data bits -- `in_ready` is low on the flush clock, so no transfer
    occurs), `test_usb_bit_destuffer.test_trailing_stuffed_zero_at_packet_end_is_removed`
    (the RX side removes it with no `stuff_err`), and
    `test_usb_bit_codec_loopback.test_round_trip_packet_ending_on_six_ones`
    (end to end: one extra bit on the line, payload recovered unchanged).
    The unflushed behavior is retained as the distinct *mid-stream* case in
    `test_usb_bit_stuffer.test_trailing_run_of_six_is_not_stuffed_without_a_flush`.
    `usb_bit_stuffer` has no packet-boundary logic of its own by design;
    the flush is a wrapper obligation documented in its header, and the
    RTL it is driven against here is bit-identical to the RTL reviewed
    before this record -- no synthesizable logic changed to reach this
    result.
  - The loopback leg additionally confirms the property bit stuffing exists
    to provide: with an all-1s payload the encoded line never holds the
    same state for more than seven bit times.
